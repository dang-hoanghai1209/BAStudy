# Test Strategy

**Status:** Verified (tooling) / Decided (layers and requirements).

## 1. Tooling — as it actually is

| Layer | Tool | Command | Present? |
|---|---|---|---|
| Backend unit + integration | Pytest + `coverage`, FastAPI `TestClient` | `cd backend && uv run bash scripts/test.sh` | ✅ 7 test files |
| Frontend component | **Vitest + React Testing Library** | `bun run test:unit` | ❌ **not installed yet** — see §2 |
| E2E | Playwright 1.61.1, Chromium | `bun run test` / `docker compose run --rm playwright bunx playwright test` | ✅ 6 specs |
| Static analysis | mypy (strict), ty, ruff, Biome | `cd backend && uv run bash scripts/lint.sh`; `bun run lint` | ✅ |

Three facts worth internalising:

- **`bun run test` runs Playwright, not unit tests.**
- **Backend tests require a real PostgreSQL database.**
  `backend/tests/conftest.py` opens a session against the configured
  engine, calls `init_db`, and **deletes all `Item` and `User` rows at
  session teardown**. There is no in-memory substitute, and the teardown is
  destructive — never point the suite at a database holding anything you
  want to keep.
- **CI enforces `coverage report --fail-under=90`.** That is a gate, not a
  target. Plan coverage into each slice rather than discovering it at CI.

## 2. The component-test gap

This strategy requires a frontend test for loading, empty and error states
on every new screen. **The runner for that does not exist in the repository
yet.** `frontend/package.json` has no Vitest, no Jest and no Testing
Library.

The decision is made and the gap is being closed deliberately: Vitest +
React Testing Library, added in its own commit (**VS-000a**), per
[`../architecture/adr/ADR-0007-FRONTEND-TEST-RUNNER.md`](../architecture/adr/ADR-0007-FRONTEND-TEST-RUNNER.md).
Adding it is a dependency change and was therefore excluded from the
documentation-only VS-000 commit.

**Until VS-000a lands, no slice may claim the "frontend test" line of the
Definition of Done.** Say so plainly in the integration report rather than
quietly marking it met.

## 3. Layers per slice

| Layer | Covers | Required |
|---|---|---|
| Unit | Every business rule or formula the slice introduces or changes, at boundary values | Always, for any rule or calculation |
| Integration | Every endpoint added or changed, including validation and error paths | Always, for any endpoint |
| Authorization | Each allowed role passes; each denied role gets 403; another organization gets 404; a superuser without a membership gets 404 | Always, for any endpoint |
| Contract | Client regenerated; the diff reviewed | Always, when the API changes |
| Frontend | Loading, empty and error states — not just happy path | Always, for any new screen (from VS-000a) |
| E2E | The slice's primary happy-path journey | Always, for any user-facing slice |
| UAT | Acceptance-criteria-level proof per [`../ba/09-UAT-STRATEGY.md`](../ba/09-UAT-STRATEGY.md) | Always — this is what separates "tests pass" from "business need met" |

## 4. Tests this project specifically requires

Where a slice touches the behaviour, these must exist and must **prove**,
not assert:

- **Idempotent import** — re-importing the same file creates no duplicates,
  at both file and row level.
- **Cost history integrity** — adding or correcting a cost does not mutate
  an existing row; ranges never overlap; resolution at a date returns the
  covering record, tested at exact boundaries.
- **Missing input is visible** — no covering cost record produces a
  reportable exception, never a silent zero.
- **Tenant isolation** — a user from one organization cannot read
  another's data with a guessed UUID; the response is 404.
- **The superuser is not exempt** — a platform superuser without a
  membership also gets 404
  ([ADR-0006](../architecture/adr/ADR-0006-AUTHORIZATION-MODEL.md)).
- **Traceability** — a calculated figure can be traced to its source rows
  and the rule versions used.
- **Aggregate/detail invariant** — drill-down sums equal the aggregate,
  tested over generated data rather than one hand-picked case.
- **Append-only ledger** — a recalculation adds an entry; it never mutates
  one.
- **Audit completeness** — each auditable action emits exactly one event,
  including via a second code path; events cannot be modified or deleted.
- **Money precision** — no `float` in any calculation path; rounding
  correct at half-unit boundaries.
- **E2E isolation** — each Playwright test sets up and tears down its own
  state and does not depend on a previous test.

## 5. Migration verification

Autogenerated migrations are candidates, not guarantees. Before commit:
read the file line by line against the checklist in
[`MIGRATION-AND-ROLLBACK.md`](MIGRATION-AND-ROLLBACK.md) §3, confirm it
matches the intended `DATA-MODEL.md` change, and **execute the downgrade
against seeded data**. CI runs `alembic upgrade head` from scratch on every
build, which catches forward breakage but never tests the downgrade.

## 6. What automated tests cannot cover

Whether a calculated number matches **business reality**, as opposed to
matching the code's own formula, is a UAT concern. A unit test can be green
while checking the wrong formula — which is why every calculation slice
cross-checks against the hand-worked examples in
[`../ba/07-PROFIT-CALCULATION-SPEC.md`](../ba/07-PROFIT-CALCULATION-SPEC.md)
during UAT, and why a slice is never done on green tests alone.

## 7. Running the full suite

```bash
docker compose up -d db mailcatcher
cd backend && uv run bash scripts/prestart.sh
cd backend && uv run bash scripts/test.sh
uv run coverage report --fail-under=90
cd backend && uv run bash scripts/lint.sh
cd .. && bash scripts/generate-client.sh && git diff --exit-code frontend/src/client/
bun run --filter frontend build
docker compose run --rm playwright bunx playwright test
```

A non-empty diff at the `generate-client.sh` step means the committed
client was stale — that is a finding, not a nuisance.

**None of this has been verified to pass on the development machine**; the
Docker daemon was unavailable during the VS-000 audit. See
[`BASELINE-VERIFICATION.md`](BASELINE-VERIFICATION.md).
