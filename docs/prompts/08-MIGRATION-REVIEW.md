# Prompt — Migration Review

Use on any autogenerated migration before it is committed. Alembic's
`--autogenerate` produces a candidate, not a correct migration.

---

```
Review this migration before I commit it:
backend/app/alembic/versions/<file>.py

Read first:
- docs/delivery/MIGRATION-AND-ROLLBACK.md §3
- docs/architecture/HISTORICAL-DATA-POLICY.md
- docs/architecture/adr/ADR-0002-TENANCY-MODEL.md
- docs/architecture/adr/ADR-0003-MONEY-AND-CURRENCY.md

Walk through the file line by line and answer each of these explicitly —
"looks fine" is not an answer:

Data loss
- Any drop_table or drop_column? Was it intended, or did autogenerate not
  see a model?
- Any type change rendered as drop-and-recreate rather than an ALTER with
  an explicit cast?
- Any new NOT NULL column without a server default or a backfill? That
  fails on a non-empty table

Project rules
- organization_id present, non-null, indexed, with a foreign key?
- shop_id present where the table is shop-specific, with the constraint
  keeping it consistent with the shop's organization?
- Money columns NUMERIC(18,4)? Any float or double precision anywhere?
- Currency column present on monetary tables?
- Timestamps timezone-aware?
- Any ON DELETE CASCADE on business data? There must not be — the template
  uses it for item.owner_id, and that pattern must not spread
- For effective-dated tables: is the non-overlap constraint present?

Correctness
- Indexes for every foreign key and every column this slice filters on?
- Is downgrade() real, or is it "pass"?
- Does down_revision point at the current head? Is there still exactly one
  head?
- Are data migrations separated from schema migrations, and idempotent?

History
- Does anything here rewrite or destroy historical calculation data? If so,
  it needs explicit human sign-off recorded in the PR description

Then tell me:
1. Whether this migration is safe to commit as-is
2. Every change you would make, with the reason
3. What to run to verify it, including the downgrade against seeded data —
   an untested downgrade is not a rollback plan
```

---

## Notes

- The three failure modes autogenerate actually causes here are: missing
  models (empty or partial migration), type changes as drop-and-recreate,
  and non-null columns without a backfill. The prompt asks about each
  directly rather than hoping they are noticed.
- Never edit a migration that has already merged. Fix forward.
