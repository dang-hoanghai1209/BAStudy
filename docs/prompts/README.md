# Prompt Library

**Status:** Draft — these are starting points, improved as they are used.

Reusable prompts for implementation work on SellerMargin. They exist so
that recurring tasks are approached the same way each time, and so that the
project's own rules (business rules first, never hand-edit generated files,
never rewrite history silently) are carried into every session rather than
remembered inconsistently.

## How to use these

1. Pick the prompt matching the task shape.
2. Fill in every `<placeholder>`. A prompt with placeholders left in is a
   prompt that will get guessed at.
3. Paste it as the opening message of a working session.
4. If the prompt produced a bad result, fix **the prompt**, not just the
   output. That is the point of keeping them in the repository.

## Rules every prompt inherits

These come from [`../../CLAUDE.md`](../../CLAUDE.md) and do not need
restating in each prompt, but they bind regardless:

- Business rules are written before the code that depends on them.
- Generated files are regenerated, never hand-edited
  ([`../architecture/GENERATED-FILES.md`](../architecture/GENERATED-FILES.md)).
- Migrations are read and manually verified before commit.
- Nothing silently rewrites historical figures
  ([`../architecture/HISTORICAL-DATA-POLICY.md`](../architecture/HISTORICAL-DATA-POLICY.md)).
- Every business table carries `organization_id`; access is deny-by-default.
- Money is `Decimal` / `NUMERIC(18,4)`, never `float`.
- Stop and ask rather than inventing a business rule.

## Writing a new prompt

A good prompt here states the task, names the documents to read **first**,
states the constraints (what must not be touched), and defines what "done"
looks like. It does not describe the whole system — the documents do that.
